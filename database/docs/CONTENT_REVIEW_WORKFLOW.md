# 内容审核与发行流程

程序校验只处理身份、引用、许可、数值约束和确定性；不代表真人理解并认可每句话。

| 层 | 文件/表 | 允许进入下一层的证据 |
|---|---|---|
| RAW | samples/原始JSONL、source_records.raw_json | 官方获取路径、记录ID、数据许可与抓取时间 |
| NORMALIZED | collection_objects及类型扩展、field_evidence | 身份/分类/时间/FK/重复项批次校验；未知继续NULL |
| EDITORIAL_DRAFT | editorial/articles.json、editorial_articles | 本件来源匹配；每个正文段落的字段证据；AI一律DRAFT_PENDING_REVIEW |
| GAME_CANDIDATE | planning/candidates.json、game_collection_candidates | 唯一候选ID，实物参考或明确虚构原型，四审PENDING |
| APPROVED | 单独人工审订后的定义 | 历史、来源、数值、玩法四审通过；审核人、备注、内容SHA、日期 |
| RELEASED | data/catalog/global_catalog.json及实际游戏资源 | 明确发行授权、媒体/1933/运输检查、正式池差异审查及回归 |

## 人工审核顺序

1. 来源审核：回到机构记录核对馆藏号、许可证、现藏机构、制造/发现地点。每张图片或3D分别核验，CC0元数据不能代替图片许可。
2. 历史/科学审核：逐句阅读正文与claims，核对制造年代、地质时代、采集与命名年。尤其检查推测语气、争议真伪、属/种/高阶分类、类型标本地位和未经确认的中文术语。
3. 编辑审核：确认推荐中文名不会覆盖官方名字；用途与独特特征有证据，不给缺失人物/铭文/地点编造答案。相关图鉴的TYPE_COMPARISON不能升级为同一实物说明。
4. 数值审核：只看候选数值带及同类跨度，游戏价值不是市场价格；体量未知先待审，大型骨架/家具不进8格。PACKED_CRATE仅策划分类，目前也没有运输玩法。
5. 玩法审核：确认获取地区、1933虚构身份与来源年代关系，候选没有自动加入掉落。现代采集实物若改为虚构类型，必须另写FICTIONAL_ARCHETYPE和独立身份说明，不能改写馆藏发现年。

真人在明确审核某一内容版本后，维护者才可以登记reviewer、review_note、内容SHA与UTC日期到content_review_log，并记录各审核环节结论。这里没有“运行校验即批准”的命令，也没有自动候选升级/发行脚本。本阶段无人审通过100篇或500件，全部保持待审状态。

内容修订后应作新审计记录，将相应审核环节重新设为PENDING；原审核记录保留。不能复用旧SHA的批准去覆盖新文字。已审核行不会被种子重放覆盖。正式策划定义仍须通过明确人工映射另行建立；本阶段禁止新掉落或发行批准。

- 100篇图鉴全部待真人逐句审订；80术语未宣称专家审定。
- 400候选没有自身专属图鉴，只链接同类比较稿。
- 66化石保留NEEDS_REVIEW；高阶Chordata、Genus sp、项目名和未定古植物不可自动细分为物种。
- 科林斯式头盔真伪、仿古玉圭断代、据称出土地、孩童袍用途等保留来源疑问。
- 化石发现年、命名年与精确年龄大多未知；采集日期不改成发现年。
- 夏/秦专题实物、菊石与遗迹化石、部分全球文明专题有缺口，不能把词表数量当作实物数量。
- 20候选的具体身份年代阻断；其余480也只是REVIEW_REQUIRED。
- 所有体量建议需审订；无图片/3D下载，未核验媒体不进入发行包。
