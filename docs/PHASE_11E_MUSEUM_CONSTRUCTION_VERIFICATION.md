## 数据模型与47项稳定设施

- MuseumFacilityDefinition：ID、厅、所属柜、类型、解锁/最大等级、价格、维护、兴趣、程序化视觉状态。
- MuseumFacilityState：实际等级、按顺序编号的费用流水；不存UI或NPC节点。
- MuseumFacilityUpgrade：当前等级/目标/报价快照，消耗或陈旧报价拒绝重付。
- MuseumConstructionService：配置、购买、兴趣封顶、预计维护；UI不负责公式。
- MuseumOperatingFinance：只在实际营业闭馆后支付一次维护并归档。
- MuseumFacilityCodec：版本7扩展，验证等级与费用链、报表一致性。

11个原DisplayUnit各四类，共44项，ID为如`CASE_2:LIGHT`，来自稳定配置ID而非随机生成。另有MAIN_GUIDE、EAST_REST、MAIN_RECEPTION三项。全部0～3级。馆舍升级体系、解锁和36/56/81位置保持原样。设施不能绕过hall/unit.unlock_level，空柜可投资但没有展品就没有凭空吸引力。

## 真实游客服务

沿用MuseumVisitor实体和本厅坐标/共享通道，新增SERVICE状态。实际走到导览/休息/接待点后完成计时才提交使用；设施只载入当前厅，稳定ID不随节点卸载变化。未升级服务完全不进入新状态。

- 接待：购票之后走到MAIN_RECEPTION，停留`0.3 + level×0.1`秒。
- 导览：主厅看展后实际阅读，停留`0.6 + level×0.1`秒；全程最多三次实际观看，不是直接灌访问计数。
- 休息：东厅看展间隙走到座椅，停留`0.8 + level×0.1`秒；每人每项一次。

完成按当日visitor_index+facility_id去重。票款仍按visitor_index一次，闭馆后迟到票款和服务记录被拒绝；被中断的服务不计完成。保护、导览、休息都不提升玩家战斗属性。不招聘员工，不实现复杂人群经济。

## 建设事务、运营费用与现金

购买必须资金足够、MORNING/EVENING、设施和展厅已解锁、等级未满、报价和当前等级一致。原馆舍投资记录HALL_EXPANSION，设施FACILITY_UPGRADE，维护MAINTENANCE；顺序交易号不会随机变化。确认成功后必须明确查看下一报价才能继续，同一UI重复信号不能连买下一级。

每个实际营业日开馆时锁定维护预算，最后游客离场结算一次：

```
maintenance_paid = min(available_cash, maintenance_due)
maintenance_waived = maintenance_due - maintenance_paid
operating_net_income = ticket_income - maintenance_paid
cash -= maintenance_paid
```

票款在实际购票时已进入现金，闭馆不会再发一次钱。ticket_income始终毛收入；净收益不包含建设资本投资。建设投资另有实际费用流水，报表construction_at_close只表示截至闭馆的当日投资，闭馆后再投资不重写已结算日报。

维护按营业日计，不开馆不收；没有升级的原始馆舍维护为0。现金不足时当天余款明确减免，不产生负现金、债务或下次补扣。运营净收益可以为负，现金不会为负。数据保存/读取不会再次支付或扣维护。

建设流水只记新建设/升级/维护，古董商、拍卖和修复继续原有事务，不假称已重建过去全部现金历史。

## 经营循环与30天真实模拟

完整GameFlow以隔离馆藏、现金0开馆，实际游客付票，闭馆后WASD/E到原建设牌，鼠标进入设施规划并用赚到的票款购买80照明；确认柜内兴趣提升，自动安全保存实际设施及现金。这条循环没有注入建设资金。

另一个30天模拟使用显式隔离资金10000、真实游客实体和购买操作：CASE_2四种设施到2级，三公共设施1级。测试加速4秒营业/1800游客速度/0.05秒观看，不改生产60秒、票价5或移动配置。

- 建设/升级投资1240。
- 240位真实付费游客，毛票款1200。
- 30个唯一营业报告，维护实付270。
- 运营净收益930。
- `10000 - 1240 + 1200 - 270 = 9690`，实际现金一致。
- 重复结算没有重复扣费；资金2、维护3的独立案例实付2、减免1，现金0且无以后补扣。

公共服务的停留在这个4秒加速夹具中会改变吞吐，不能据此宣称正式60秒经营已完成经济平衡。人工尚待回来验收。
